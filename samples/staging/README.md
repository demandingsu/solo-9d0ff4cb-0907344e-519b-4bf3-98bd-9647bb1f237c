# 待结清（补单结清）演示样例

模拟入库单、转仓单、交货单分开送到、最后补单结清的完整过程。
在「上传台账」页的**待结清**入口（或「待结清」页）按顺序暂存四批，
每批沿用三份 CSV，单据还没到的文件只传表头：

| 顺序 | 送到的单据 | 上传文件 | 暂存后效果 |
|---|---|---|---|
| 1 | 入库单 | `1_inbound.csv` + 两个表头文件 | S1 +100、S3 +80 |
| 2 | 转仓单 | `2_transfers.csv` + 两个表头文件 | 与批 1 并成一组（共享 S1），S2 -40 |
| 3 | 部分交货单 | `3_deliveries.csv` + 两个表头文件 | S1 结平，S2、S3 仍有差额 |
| 4 | 剩余交货单 | `4_deliveries.csv` + 两个表头文件 | 整组各仓次差额为 0 |

演示要点：

1. 暂存批 1、批 2 后，「待结清」页可见两批因共享仓次 S1 并成一组，各仓次差额实时列出。
2. 在批 3 暂存**之前**打开待结清列表，然后在另一个标签页暂存批 3，
   再回到原标签页按旧分组点「确认结清并入账」——确认被退回并提示刷新（有补报并入该组）。
3. 刷新后确认，会因 S2、S3 差额被退回（原账与暂存照旧）。
4. 暂存批 4 后整组平衡，确认成功：整组从待结清列表移走，计入核对包汇总
   （果园A：市场甲 55、市场乙 40、仓存 5；果园B：市场甲 30、市场丙 45、仓存 5）。
